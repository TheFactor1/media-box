Status: desk research, 2026-10-27. Nothing here was measured by us. Each claim links to its source; **[M]** = measured by a reviewer/dev, **[A]** = forum anecdote, **[S]** = vendor spec sheet. Prices are US snapshots with the date of the snapshot; many are 2024–2025 and must be re-checked at purchase.

Honest reading: **no AMD 780M box has a clean HDR report on stock Kodi/GBM**, and AMD TrueHD/DTS-HD passthrough on Linux has an open Kodi bug since 2022 (dGPU; iGPUs untested). The Intel Core Ultra box has a correct-but-8-bit HDR report. Neither tier-2 option is "verified"; both need a Phase 0 bench test before being listed. If tier 2 is mainly about Jellyfin transcodes and a bigger disk, a **NUC 14 Essential N355 / N305-class** box with the proven Gen12 media path is the lower-risk answer.

## 1. The sweet spot

**Decode (VA-API).** Intel Gen12 UHD (N100/N150/N200/N305/N355, all Alder/Twin Lake-N) decodes HEVC 8/10-bit, VP9 8/10-bit and AV1 8/10-bit in hardware and *encodes* HEVC/H.264 but **not AV1**; a Jellyfin moderator: N100 decodes Jellyfin's entire list "EXCEPT VP8" ([Jellyfin forum, 2024](https://forum.jellyfin.org/printthread.php?tid=7526)). Intel's own N150 page lists 24 EUs, 1 GHz, HDMI 2.1, 4096×2160@60 ([Intel ARK](https://www.intel.com/content/www/us/en/products/sku/241636/intel-processor-n150/specifications.html)). The Intel media driver 2026Q1 still carries HEVC/AV1/VP9 decode fixes for all gens ([Phoronix, Apr 2026](https://phoronix.com/news/Intel-Media-Driver-2026Q1)). Core Ultra (Xe-LPG) adds AV1 encode and more throughput but nothing the TV path needs. AMD 780M (VCN 4.0) decodes AV1/HEVC/VP9 10-bit and encodes AV1 per AMD's table ([AMF wiki](https://github.com/GPUOpen-LibrariesAndSDKs/AMF/wiki/GPU-and-APU-HW-Features-and-Support)); Ryzen AI 300 (VCN 5) likewise ([Notebookcheck](https://www.notebookcheck.net/Ryzen-AI-7-PRO-360-vs-R7-8745HS-vs-R9-8945H_18004_19649_17942.247596.0.html)) — spec claims, no vainfo found.

**HDR10 on Kodi GBM.** Intel: official since LibreELEC 11 (Kodi 20, GBM) for Intel and AMD ([Phoronix, 2023](https://www.phoronix.com/news/LibreELEC-11-Released)); Gen12 listed HDR=Yes in the LE hardware doc ([LibreELEC docs](https://github.com/LibreELEC/documentation/blob/master/hardware/intel-x86-64-generic/README.md)). Current state on N100/N150: works, with two live bugs (§6). Kodi 22 RC1 (10 Oct 2026) claims "full HDR end-to-end" and HDR overlays ([BetaNews](https://betanews.com/article/kodi-22-piers-rc-1-features/), [Kodi beta 2](https://kodi.tv/article/kodi-22-piers-beta-2/)); LibreELEC says LE13 = Kodi 22, beta "once a few things are squared away" ([LE forum, Oct 2026](https://forum.libreelec.tv/thread/30654-next-libreelec-release/)). AMD RDNA2/3: HDR switches but the SER8/780M report says the picture is wrong (§ tier 2); a 5600G needed 120 Hz mode tricks in 2023 ([LE forum](https://forum.libreelec.tv/thread/27046-hdr-with-samsung-tv-and-amd-ryzen/)). chewitt's ranking, Feb 2024: "Intel first, AMD second, Nvidia a distant third" ([LE forum](https://forum.libreelec.tv/thread/28146-gpu-recommendations-for-4k-hdr/)).

**Passthrough.** Intel N100 (UN100C): DTS:X and TrueHD Atmos passthrough working on LE nightly ([Kodi forum, Dec 2023](https://forum.kodi.tv/showthread.php?tid=375492)) — **but** all Gen12+ drop HD audio at 2160p/23.976 unless output is capped to 10-bit (§6). AMD: Kodi issue #21135 (TrueHD/DTS-HD MA silent over ALSA, RX 6700 XT, 2022) was auto-closed Aug 2026 and reopened Sep 2026; one user fixed it with "Sync playback to display"; mpv passes the same streams fine, pointing at Kodi's ALSA path ([GitHub](https://github.com/xbmc/xbmc/issues/21135)). No 680M/780M data either way.

**Where the next dollar stops.** For the TV path, N100 → N150 buys ~nothing (same 24-EU iGPU; N150 is a clock bump). N305/N355 (32 EU, 8 cores) buys Jellyfin transcode headroom, not playback. Core Ultra / 780M buys nothing for playback and adds HDR risk. Dual-channel RAM matters only for tone-mapped transcodes (§5). 8 GB is enough for Player mode (§5); a 500 GB NVMe is only for OS + Jellyfin metadata since v1 stores no media.

## 2. HDMI reality

- **Alder/Twin Lake-N has native HDMI (2.1 TMDS = 2.0 bandwidth, 18 Gbps) from the SoC** ([Intel ARK N150](https://www.intel.com/content/www/us/en/products/sku/241636/intel-processor-n150/specifications.html)). So on N100/N150 boxes the HDMI ports are normally native; the LSPCON story is a Gen7/Gen8 NUC thing ([LE wiki](https://wiki.libreelec.tv/hardware/intel-x86-64-generic)). Kernel LSPCON HDR support landed in 5.12; old LSPCON firmware is the usual failure ([same page](https://wiki.libreelec.tv/hardware/intel-x86-64-generic)).
- **The real trap is a DP-to-HDMI converter sold as "HDMI 2"**: HUNSN BM34's HD2 enumerates as DisplayPort, no BT.2020, no bitstream audio; HD1 fine ([LE forum, Feb 2024](https://forum.libreelec.tv/thread/28097-intel-n100-fanless-boxes/)). Test: `cat /sys/class/drm/card*/status` + `edid-decode`; a port named `DP-x` is a converter.
- **4K60 10-bit HDR is 4:2:0 only at 18 Gbps** on every box here (no FRL): Intel i915 refuses high TMDS clocks and falls to 8-bit at 4K60 ([LE forum, Apr 2025](https://forum.libreelec.tv/thread/25185-x86-64-hdr-playback/?pageNo=25)); amdgpu's HDMI port is held to TMDS by the HDMI Forum (FRL only via DP→HDMI 2.1 PCON) ([same thread](https://forum.libreelec.tv/thread/25185-x86-64-hdr-playback/?pageNo=25)). Film at 23.976 Hz runs 4:2:2/4:4:4 12-bit fine; the 10-bit cap (§6) is still needed for audio.
- **Port to use:** EQ14 / S13 / G3 Plus — either HDMI (both native; prefer HDMI 1, nearest the SoC in teardowns, verify with `edid-decode`). NUC 14 Essential — the HDMI 2.1 (TMDS) port, not USB-C. SER8 / UM890 / K8+ — the HDMI 2.1 port (DP→HDMI gave *different* wrong colours, not better) ([LE forum, Apr 2025](https://forum.libreelec.tv/thread/25185-x86-64-hdr-playback/?pageNo=25)). NUC 14 Pro — either HDMI 2.1 TMDS; the AVR-in-path resync problem is on both.

## 3. CEC

- **Built-in CEC exists only on Intel/ASUS NUC Pro/Enthusiast lines (NUC7–NUC13 list, Feb 2024) and it does power on/off only**, no remote keys ([ASUS FAQ](https://www.asus.com/support/faq/1052555)). NUC 14 Pro Plus lists "TMDS with CEC" ([ASUS](https://www.asus.com/vn/displays-desktops/nucs/nuc-mini-pcs/asus-nuc-14-pro-plus/where-to-buy/)); NUC 14 Essential spec has no CEC ([ASUS techspec](https://www.asus.com/displays-desktops/nucs/nuc-mini-pcs/asus-nuc-14-essential/techspec/)). ASUS PN42 (N100): power-only CEC in BIOS, LG C3 would not wake it ([LE forum, May 2024](https://forum.libreelec.tv/thread/28097-intel-n100-fanless-boxes/)). No Beelink/GMKtec/MINISFORUM box advertises CEC.
- **Pulse-Eight USB-CEC adapter: USD $48.42 (vendor page, Oct 2026)**, Linux/libcec supported, but "does not support resolutions and colour spaces greater than 4K60 4:2:0 8-bit" and is a passive ~2 m-at-UHD device ([Pulse-Eight](https://www.pulse-eight.com/p/104/usb-hdmi-cec-adapter)). **It cannot sit in a 4K HDR video path.** Workaround used by HTPC builders: hang the adapter on a spare TV HDMI input with no video through it, CEC bus only ([Kodinerds, de](https://www.kodinerds.net/thread/80107-bekomme-cec-nicht-ans-laufen/)) — to test.
- **Remotes that work with zero config:** Flirc USB (IR→keyboard, Linux supported, ~$18–23; ships with a Kodi profile) ([Core Electronics](https://core-electronics.com.au/flirc-usb.html), [deal page](https://deals.androidauthority.com/sales/flirc-ir-receiver)); OSMC RF remote (2.4 GHz dongle, Kodi keymap, ~£19, stock thin) ([Pi Hut](https://thepihut.com/products/osmc-rf-remote-control)) — it also wakes a PN42 from S5 ([LE forum](https://forum.libreelec.tv/thread/28097-intel-n100-fanless-boxes/)); Rii-class 2.4 GHz air-mouse/keyboard remotes (HID, no driver) ([Comparitech](https://comparitech.com/kodi/best-kodi-remotes)). Bluetooth remotes need a pairing UI — the wizard would have to own that.

**Honest minimum:** Player mode 8 GB is safe (Kodi + OS well under 2 GB by every report). Plan 1–2 concurrent phone transcodes on N100/N150, not 3–4.

## 6. Things that change the plan

1. **Intel Gen12+ HD-audio dropouts at 2160p/23.976 Hz** — exactly our hero use case (4K HDR remux, TrueHD). Open since Dec 2023, Intel engaged but no upstream fix as of Jan 2026; LibreELEC 13 ships a **kernel patch capping HDMI output at 10-bit**, which removes the dropouts on chewitt's Beelink N150 ([LE forum 2023–24](https://forum.libreelec.tv/thread/27886-intel-alder-lake-2160p-23-976-hz-passthrough-hd-audio-dropouts-i7-1270p-n100/), [LE forum 2026](https://forum.libreelec.tv/thread/30274-x86-64-best-le-13-nightly-for-intel-n150-alder-lake-n/)). **Our Fedora bootc image must carry that patch (or sky42's runtime 10-bit cap script) or the reference tier fails its own target.** Add to Phase 0 spikes.
2. **HDR start/stop dropouts and AVR resync on Intel** (black screen / no sound at HDR mode switch; Denon resync) persist on LE13 nightlies as of Aug 2026 ([same thread](https://forum.libreelec.tv/thread/30274-x86-64-best-le-13-nightly-for-intel-n150-alder-lake-n/)). Mitigation candidates: keep the GUI in HDR-capable mode, sky42's resync script. Test with an AVR in path, not TV-direct.
3. **AMD tier 2 is not verifiable today**: wrong HDR colours on 780M (Apr 2025, unfixed in thread) and an open AMD passthrough bug. Demote tier 2 to "Intel N355/Core Ultra, AMD after bench test". Core Ultra's own caveat: HDR at 8-bit only and AVR resync loss (Apr 2025).
4. **CEC is effectively off the table**: no cheap box has it, and the only adapter blocks >4K60 8-bit. Ship/recommend a Flirc or OSMC-style RF remote and design wake/sleep around the remote (OSMC remote wakes from S5). Revisit only if the spare-input CEC trick tests clean.
5. **No LSPCON scare on N-series**: HDMI is native from the SoC; what to screen for is a DP-converter second port. Put an `edid-decode`/connector-name check in the wizard's status screen.
6. **No HDMI 2.1 FRL on any candidate** (Intel TMDS-only, amdgpu HDMI held to TMDS). 4K60 HDR = 4:2:0; irrelevant for film, relevant if the GUI runs 4K60 10-bit. Keep GUI at 1080p60 or 4K60 8-bit.
7. **Idle power reality**: N150 boxes measure 10–14 W at the wall idle under Linux/Windows, not the 6 W TDP ([igorslab](https://www.igorslab.de/en/beelink-eq14-mini-pc-im-test/6), [Lon.tv](https://blog.lon.tv/tag/review/page/6/), [Netgate forum](https://forum.netgate.com/post/1227838)); powertop/ASPM tuning is a Phase-1 task.
8. **Timing**: Kodi 22 RC1 10 Oct 2026; LE13 beta pending. The 10-bit cap patch and resync fixes live in LibreELEC's tree, not upstream — we will be cherry-picking from [LibreELEC.tv](https://github.com/LibreELEC/LibreELEC.tv) kernel patches.

## Unknowns and what to test (Phase 0, per reference model, with AVR in path)

1. `vainfo` + Kodi debug log: HEVC Main10 / AV1 / VP9 10-bit decode engaged, GUI fps at 1080p60 with the target skin during 4K playback (CPU %, `intel_gpu_top`).
2. HDR10 start/stop ×20 with TV-direct and via AVR: black screen, lost audio, resync time. With and without the 10-bit cap.
3. 2160p/23.976 TrueHD Atmos and DTS-HD MA remux, 30 min each, count dropouts, with/without the 10-bit cap patch; repeat at 2160p/59.94 and 1080p/23.976.
4. `edid-decode` on each HDMI port; confirm connector type HDMI-A, BT.2020 + HDR static metadata exposed, bitstream formats listed by `aplay -L` / Kodi audio device list.
5. RAM: `smem`/`ps_mem` of kodi + jellyfin idle and during one tone-mapped phone transcode on 8 GB — decides whether "8 GB Hub" can ever be advertised.
6. Transcode headroom: N150 with VPP tone mapping, 1/2/3 concurrent 4K HDR→1080p; QSV vs VAAPI; AV1 encode disabled.
7. Wall power idle (Kodi on, screen blanked) before/after powertop auto-tune; fan dB at 1 m during 4K playback.
8. Remote: OSMC RF and Flirc wake from S3/S5; key map complete without a keyboard; Pulse-Eight on a spare TV input (CEC-only) if CEC is still wanted.
9. Cold boot to Kodi home (power button → first frame) on EQ14 and NUC 14 Essential against the < 20 s target.
10. AMD only if time permits: SER8 HDR colour check against the same file on Windows; TrueHD passthrough with and without "Sync playback to display".
